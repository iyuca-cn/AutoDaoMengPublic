## 日志模块

仓库内提供了一个基于 `loguru` 的日志配置模块：`src/log/log.py`。

## 当前配置

该模块会把日志写入仓库根目录下的 `logs/` 目录，并按级别拆分输出：

- `trace.log`：仅 `TRACE`
- `debug.log`：仅 `DEBUG`
- `info.log`：仅 `INFO`
- `success.log`：仅 `SUCCESS`
- `warning.log`：仅 `WARNING`
- `error.log`：仅 `ERROR`
- `critical.log`：仅 `CRITICAL`
- `all.log`：汇总 `DEBUG` 及以上所有日志

控制台输出规则：

- `DEBUG`、`INFO`、`SUCCESS` 输出到标准输出。
- `WARNING`、`ERROR`、`CRITICAL` 输出到标准错误。
- `TRACE` 默认只写文件，不上屏。

## 使用方式

如果你希望在自己的代码里复用这套配置，可以导入该模块暴露的 `logger`：

```python
from log.log import logger

logger.debug("调试信息")
logger.info("普通信息")
logger.success("操作成功")
logger.error("发生错误")
```

## 当前项目里的实际情况

- `src/DMAPI/DMLocalClient.py` 已经接入 `src/log/log.py`，会为本地 `DMLocalApi` 调用记录统一日志。
- 当前 DMapi 日志会记录 `operation`、HTTP 方法、路由、耗时、成功/失败状态，以及脱敏后的请求参数摘要和响应摘要。
- `credit_workflow`、`random_drain` 等工作流本身仍未逐模块普遍接入该日志模块，但它们经由 `DMAPI` 发起的底层接口调用已经会进入这套日志。
- 仓库根目录现有的 `logs/` 文件仍然可能混有历史运行遗留物，排障时请结合时间戳判断来源。

## 安全提醒

- 历史 `logs/*.log` 中已经发现过明文 `uid`、`token`、`api_token` 以及完整请求载荷残留。
- 当前 `DMLocalClient` 新增的 DMapi 调用日志默认会对登录态、用户标识列表和导出链接做脱敏，并只记录响应结构摘要。
- 即便如此，分享日志前仍建议再次检查是否包含不适合外传的业务信息。

# 命令行工作流说明

本文档对应当前 `src/main.py` 的 3 个命令：`plan`、`execute`、`random-drain`。

## `plan`

命令：

```shell
uv run src/main.py plan --excel /path/to/input.xlsx --output /path/to/output
```

用途：

- 读取 Excel 需求表。
- 拉取当前可管理活动、签到卡状态、录取名单和学分项。
- 生成冻结后的 `plan.json` 和一组预览报表。

输入 Excel 要求：

- 必填表头：`学号`、`姓名`、`学分类型`、`学分数值`。
- 表头顺序不限。
- `学分数值` 必须精确到 `0.01`。
- `学分类型` 支持单个类型，也支持用 `,` 或 `，` 分隔多个类型作为优先级回退顺序。

当前支持的学分类型：

- `美育实践学分`
- `思想成长学分`
- `劳动教育学分`
- `体育活动学分`

筛选规则：

- 没有签到卡的活动不会进入规划。
- 不在支持列表内的学分项不会进入规划。
- 学生必须同时满足活动录取名单匹配和学分类型匹配，才会进入可执行分配。

默认批次目录命名：

```text
<Excel文件名>_YYYY-MM-DD_HHMMSS
```

主要输出文件：

- `plan.json`：执行阶段的唯一输入。
- `plan_summary.xlsx`：总览需求、活动资源、学生分配计划、活动均衡统计。
- `activities.xlsx`：规划阶段可用活动和学分项清单。
- `not_in_admit_list.xlsx`：规划期无法在录取名单中匹配到的需求。
- `over_issued.xlsx`：计划值大于应发值的需求。
- `under_issued.xlsx`：计划值小于应发值的需求。
- `already_partially_issued.xlsx`：规划前就已部分发放的学生。
- `already_fully_issued.xlsx`：规划前就已全部发放的学生。
- `activities/<activityId>_<活动名>/...`：按活动拆分的同类报表。

## `execute`

命令：

```shell
uv run src/main.py execute --plan /path/to/output/<batch>/plan.json
```

用途：

- 读取冻结后的 `plan.json`。
- 再次校验录取名单、签到状态、已发放状态和签到卡状态。
- 在确认后执行补签和学分发放。

执行前行为：

- 程序会先打印自然语言摘要。
- 如果 `plan.json` 中预计发放次数为 `0`，程序会直接退出，不进入确认。
- 必须输入精确确认词 `EXECUTE` 才会真正执行。

执行期会重新校验的内容：

- 学生是否仍在录取名单内。
- 学分是否已全部发放或部分发放。
- 是否还能读取签到名单和已发放名单。
- 计划中的 `user_id` 是否可用；如果无效，会尝试从签到名单重新映射。
- 活动是否仍然存在签到卡；无签到卡会直接记为失败。

主要输出文件：

- `execution_results.xlsx`：补签成功、发放成功、执行期不在录取名单、执行期容量冲突、已部分发放、已全部发放、最终失败。
- `retry_results.xlsx`：依赖重试后成功的补签或发放记录。
- `final_student_summary.xlsx`：以学生为粒度汇总应发值、实际发放值、最终偏差和状态。
- `activities/<activityId>_<活动名>/...`：按活动拆分的失败和冲突明细。

## `random-drain`

命令：

```shell
uv run src/main.py random-drain --threshold-percent 90 --jitter-count 5 --output logs/random-drain
```

可选参数：

- `--threshold-percent`：每个活动学分项的最终目标已发放人数百分比，必填。
- `--jitter-count`：在目标人数基础上做 `[-N, +N]` 随机偏移，默认 `0`。
- `--seed`：随机种子，便于复现抽样结果。
- `--output`：输出目录，默认 `logs/random-drain`。

规则说明：

- 基础目标人数按总名额乘百分比，并采用四舍五入到整数。
- 随机偏移后会自动夹紧到 `[0, 总名额]`。
- 只有有签到卡、且学分类型在支持列表内的活动学分项才会进入抽样。
- 已发放人数达到目标阈值时会标记为 `threshold_reached`，不会继续抽样。
- 候选不足时会标记为 `candidate_shortage`，并尽量发放全部候选人。

确认方式：

- 程序按活动逐个展示摘要。
- 每个活动都需要输入精确确认词 `EXECUTE <activityId>`。
- 没有确认的活动会被记入 `random_drain_skipped.xlsx`，不会修改线上状态。

主要输出文件：

- `random_drain_summary.xlsx`
- `random_drain_successes.xlsx`
- `random_drain_failures.xlsx`
- `random_drain_skipped.xlsx`

## 常见建议

- 先跑 `plan`，人工检查 `not_in_admit_list.xlsx`、`under_issued.xlsx`、`over_issued.xlsx` 后再执行。
- `execute` 前不要手动修改 `plan.json`，否则后续报表与执行事实可能不一致。
- 如果只想复用外部已启动的本地服务，可设置 `DMLOCALAPI_DISABLE_AUTOSTART=1` 并提供 `DMLOCALAPI_BASE_URL`。
- 如果需要共享问题日志，请先检查并脱敏 `logs/` 目录中的 `uid`、`token` 和请求载荷。
